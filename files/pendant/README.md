# Синхронизация настроек Pendant через Pi Sync

Без дополнительного расширения VS Code, демона или отдельного облачного хранилища.

- `settings.json` — переносимые **явно заданные пользовательские** настройки Pendant.
- `bridge/` — исходники CLI `pendant-settings`, тесты и зафиксированные зависимости.
- Pi Sync переносит весь каталог `pendant` в уже настроенное хранилище. `node_modules` исключается самим Pi Sync.
- CLI ничего не отправляет в сеть: он согласовывает локальные настройки VS Code с `settings.json`. Загрузка/выгрузка выполняется отдельно через `/sync`.

## Использование

```bash
# Перед отправкой конфигурации с этого компьютера:
pendant-settings sync
# Затем в Pi/Pendant: /sync diff, после проверки /sync push

# После получения конфигурации на другом компьютере:
# В Pi/Pendant: /sync pull
pendant-settings sync

# Проверить различия без записи файлов (значения не печатаются):
pendant-settings status
```

Переносимый файл: `~/.pi/agent/pendant/settings.json`. Это НЕ файл настроек самого VS Code: его нельзя копировать поверх `User/settings.json`.

При первом запуске независимые настройки объединяются. В дальнейшем используется локальная база последней успешной синхронизации: независимые изменения с обеих сторон объединяются, удаление отдельного ключа сбрасывает только соответствующий пользовательский override.

Если один ключ изменён с обеих сторон по-разному, команда завершается с кодом **2**, не меняя настройки. После проверки обеих версий:

```bash
pendant-settings sync --prefer local   # предпочесть значение VS Code в конфликтующих ключах
pendant-settings sync --prefer synced  # предпочесть значение переносимого файла
```

Эти параметры разрешают только конфликты; независимые изменения всё равно объединяются. Другие ошибки дают код **1**, успех — **0**. Удаление всего переносимого файла после установленной базы считается ошибкой, а не командой сбросить настройки.

## Что переносится

Разрешённый список зафиксирован в `bridge/policy.json` по схеме Pendant **0.94.2**. Среди настроек: закреплённые модели, thinking, параметры интерфейса, уведомлений, языка/модели диктовки и субагентов. Значения по умолчанию не экспортируются, если пользователь не задал их явно. Новые неизвестные ключи автоматически не включаются.

**Остаются локальными:**

- `pendant.agentDir`, переменные `pendant.piEnvironment`;
- пути к голосовой модели, выбор микрофона, путь к звуковому файлу;
- shell hooks, команды подготовки worktree;
- sandbox policy и списки разрешённых/запрещённых путей;
- пути к дополнительным расширениям, skills и prompt templates;
- `pendant.systemPrompt` и `pendant.appendSystemPrompts`;
- все остальные настройки VS Code, workspace-настройки, overrides других профилей и языков;
- auth-файлы, история, сессии, кэши и временное состояние.

Профили субагентов могут содержать пользовательский текст: не помещайте туда секреты. Allowlist не является универсальным поиском секретов; проверка Pi Sync должна оставаться включённой.

Редактор JSONC сохраняет посторонние ключи, комментарии и форматирование, насколько позволяет точечное изменение свойства. Повреждённый JSONC, дубли ключей, неизвестная версия переносимого файла и симлинки целевых файлов отклоняются без замены настроек.

## Установка на другом компьютере

После получения каталога через Pi Sync нужны Node.js **22+** и npm:

```bash
AGENT="$HOME/.pi/agent" # замените, если используете другой agentDir
npm ci --ignore-scripts --no-audit --no-fund --prefix "$AGENT/pendant/bridge"
node "$AGENT/pendant/bridge/cli.js" status
node "$AGENT/pendant/bridge/cli.js" sync

# Необязательная короткая команда на Linux/macOS:
mkdir -p "$HOME/.local/bin"
chmod +x "$AGENT/pendant/bridge/cli.js"
ln -s "$AGENT/pendant/bridge/cli.js" "$HOME/.local/bin/pendant-settings"
```

По умолчанию выбирается стандартный файл VS Code: Linux — `$XDG_CONFIG_HOME/Code/User/settings.json` (или `~/.config/Code/User/settings.json`), macOS — `~/Library/Application Support/Code/User/settings.json`, Windows — `%APPDATA%/Code/User/settings.json`.

Для Cursor, VSCodium, VS Code Insiders, нестандартного user-data-dir или профиля укажите файл явно:

```bash
pendant-settings sync --settings /absolute/path/to/User/settings.json
```

Agent directory выбирается в порядке: `--agent-dir`, пользовательский `pendant.agentDir` из выбранного файла, `PI_CODING_AGENT_DIR`, `~/.pi/agent`. Пути должны быть абсолютными либо начинаться с `~/`. Каждый файл настроек редактора имеет свою локальную базу. Каталог `pendant-local-state` **не включать** в Pi Sync.

## Безопасность и восстановление

CLI делает приватную резервную копию полного файла VS Code перед его изменением. Копии и база находятся в `<agent-dir>/pendant-local-state/`, вне синхронизируемого `pendant/`; файлы создаются с правами `0600`. Эти резервные копии могут содержать секреты из других настроек VS Code: не публикуйте их. Они не удаляются автоматически.

Запись происходит через временный файл и атомарную замену с повторной проверкой исходного содержимого. Параллельные CLI разделяют lock `<agent-dir>/pendant-local-state/bridge.lock`. После аварии lock может остаться: убедитесь, что ни одна команда `pendant-settings` не работает, и только затем удалите пустой каталог lock через `rmdir`. Базу и резервные копии для этого удалять не нужно.

Lock не блокирует сам VS Code и Pi Sync. Не редактируйте настройки и не запускайте `/sync pull` одновременно с CLI: между последней проверкой и заменой остаётся короткое окно внешней записи. При обнаруженном изменении команда останавливается; после восстановления согласованного состояния её можно повторить. Переносимый файл — обычный custom content Pi Sync: конфликты этого файла между компьютерами разрешаются самим Pi Sync отдельно от локального трёхстороннего merge.

Синхронизация **по явной команде**, не постоянная. CLI не меняет режимы автоматических передач Pi Sync и не перезапускает Pendant/VS Code. Большинство настроек редактор подхватывает автоматически; для параметров запуска Pi может понадобиться перезапуск сессии.
